# 数据加载方式详解

## 🔄 数据加载流程

### 第一阶段：获取要素总数
```typescript
// 第一个JSON请求 - 获取要素总数
const featuresUrl = `${apiConfig.baseUrl}/${apiConfig.dataService}/datasources/${datasource}/datasets/${encodeURIComponent(dataset)}/features.json`;
// 响应格式: { featureCount: 1000, childUriList: [...], startIndex: 0 }
```

### 第二阶段：分页获取要素链接
```typescript
// 第二个JSON请求 - 获取分页数据
const pageUrl = `${apiConfig.baseUrl}/${apiConfig.dataService}/datasources/${datasource}/datasets/${encodeURIComponent(dataset)}/features.json?fromIndex=${fromIndex}&toIndex=${toIndex}`;
// 响应格式: { childUriList: ["path1", "path2", ...], startIndex: 0 }
```

### 第三阶段：获取实际要素数据
```typescript
// 第三个JSON请求 - 获取具体要素数据
const geometryUrl = uri.endsWith('.json') ? uri : `${uri}.json`;
// 响应格式: { geometry: {...}, fieldValues: [...], ID: 123, ... }
```

## 🛠️ 技术架构

### OpenLayers使用方式
- **主要使用**: 原生OpenLayers (`ol: ^10.6.1`)
- **辅助使用**: SuperMap for OpenLayers (`ol.supermap.*`)
- **架构设计**:
  ```
  数据获取: SuperMap for OpenLayers (ol.supermap.*)
      ↓
  数据转换: 原生OpenLayers (ol.geom.*, ol.Feature)
      ↓  
  地图渲染: 原生OpenLayers (ol.layer.*, ol.Map)
  ```

## 🗂️ 数据存储层次结构

```
内存状态管理 (Pinia Store)
├── mapStore.vectorlayers[] (图层元数据)
├── mapStore.map (地图实例)
└── mapStore.selectlayer (选择图层)
│
├── OpenLayers实例
│   ├── ol.Map (地图容器)
│   ├── ol.layer.Vector (矢量图层)
│   └── ol.source.Vector (数据源)
│
└── 要素数据
    ├── ol.Feature (要素实例)
    ├── ol.geom.Polygon/LineString/Point (几何数据)
    └── properties (属性数据)
```

## 📊 数据流转过程

```
SuperMap服务器 → 内存状态 → OpenLayers → 地图渲染
     ↓           ↓          ↓         ↓
   JSON数据  → 状态管理 → 要素实例 → 可视化显示
```

## 📋 总结

**地图数据存储位置：**
- **几何数据**: OpenLayers要素的geometry属性
- **属性数据**: OpenLayers要素的properties属性
- **图层管理**: Pinia状态管理的mapStore.vectorlayers数组
- **地图实例**: OpenLayers的Map对象

**OpenLayers实例变量：**
- **主容器**: `map` - 唯一的OpenLayers地图实例
- **所有图层**: 都通过 `map.addLayer()` 添加到这个实例中
- **图层管理**: 通过 `vectorlayers` 数组管理所有SuperMap图层
- **交互图层**: `selectlayer`, `hintersecter`, `measurelayer` 等
- **底图**: `baselayer` 作为基础底图

**图层分组管理：**
- **SuperMap服务图层**: 从SuperMap服务器加载的矢量图层
- **分析及绘制图层**: 用户绘制、缓冲区分析、相交分析、擦除分析结果
- **查询图层**: 区域选择、属性查询结果图层
- **本地图层**: 上传文件、长江数据、监测点等所有本地数据
- **外部图层**: 外部服务提供的图层

**属性数据管理特点：**
- **多层存储**: OpenLayers要素 + Pinia状态管理
- **统一接口**: 通过layerDataStore提供统一的属性访问API
- **类型安全**: TypeScript接口定义确保属性类型正确性
- **快速查询**: 支持按字段值查找、统计等操作

**外部数据来源：**
- **SuperMap服务器**: 主要的矢量图层数据，通过REST API获取
- **本地JSON文件**: 长江水系、监测点等静态数据
- **用户上传**: GeoJSON文件上传功能
- **分析结果**: 缓冲区、相交、擦除等空间分析结果

**数据特点：**
- **直接加载**: 从SuperMap服务器直接获取数据，无缓存机制
- **格式转换**: SuperMap → OpenLayers
- **内存管理**: 数据存储在内存中，页面刷新后重新加载
- **统一容器**: 所有地图数据最终都渲染在 `map` 这个唯一的OpenLayers地图实例上
- **分组管理**: 按数据来源和用途进行逻辑分组，便于用户管理

**数据流转过程：**
```
外部数据源 → 属性解析 → OpenLayers要素 → Pinia状态管理 → 用户界面显示
```
